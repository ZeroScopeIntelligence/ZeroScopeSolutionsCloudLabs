## Lab Workflow

1. Review the objective and prerequisites.
2. Use a dedicated lab account, tenant, organization, or project.
3. Create test identities and groups.
4. Grant only the permissions required at the narrowest practical scope.
5. Test both allowed and denied actions using non-administrator identities.
6. Record results and remove temporary access and resources.

## Security Rules

- Do not use the root account or primary administrator identity for routine exercises.
- Enable MFA for privileged accounts.
- Never commit passwords, access keys, tokens, private keys, or recovery codes.
- Do not grant broad administrator permissions to solve permission errors.
- Review costs before creating billable resources.
- Use only accounts and environments you are authorized to manage.
